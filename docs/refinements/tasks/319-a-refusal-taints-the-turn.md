# A tool result that carried no external content still taints the turn

**Status:** open, a seam or port change comes first
**Area:** untrusted-content
**Origin:** [ADR-0013](../../adr/ADR-0013-untrusted-content.md)

Opened 2026-08-19 by the close of [312](312-search-refusal-is-untyped.md), which gave the email
sidecar a refusal it writes itself and made this visible by writing it: the sentence a model reads
when its search is refused is text from this repo, and the turn treats it as mail.

The path is short and none of it is wrong on its own. `McpToolRegistry.invoke` builds every
`ToolResult` at the `Trust.UNTRUSTED` default, correctly, since a sidecar's claim about its own
content is attacker-influenceable and the trust decision belongs to the brain (the same argument
ADR-0027 makes for a declared source being claimed rather than attested). `dispatch_round` then
observes every dispatched result outside every branch, deliberately, so no dispatch goes
unrecorded. `TaintLedger.mark` flips on the trust alone. So a search the server refused, which
read no message and returned nothing but our own correction, closes the outbound surface for the
rest of the turn: a later `send_email` is denied with `DENIED_MSG` rather than confirmed, and the
user is told to ask again in a fresh message.

The cost is small and real. A model that mistypes a query and then wants to send loses the send to a
mailbox it never read. The conservative default is the right one at every individual step, which is
why this is a seam question rather than a bug: there is no channel today on which a sidecar could
say "this result is my own refusal, not content I fetched", and inventing one that a hostile sidecar
could set is worse than the false positive. The candidates are a brain-side one (the built-in tools
already stamp `Trust.TRUSTED` for system-generated bytes, and a refusal a gateway *itself* generated
is the same category) or a wire one narrow enough that forging it buys nothing.

**What would close it.** A decision, recorded, about whether an untrusted-by-default result may ever
be exempt from taint, and if so on what evidence. Declining it is a perfectly good outcome and
should be written down as one: the rule is a security boundary, and "a mistyped search costs you the
send this turn" may be the price. What it must not stay is undecided by default, because nothing in
the code says the case was considered.
