# A reply says a row the forget kept was forgotten

**Status:** open, actionable
**Area:** memory
**Origin:** [ADR-0075](../../adr/ADR-0075-forget-chosen-memories.md)
**Verified:** 2026-11-24

On the [kept reason draws](../../readings/forget-result-texts.md#the-reason-given-for-rows-kept-under-an-unread-role-2026-11-24),
the cortex read a result saying a row was kept and then replied that it was forgotten in 24 of 32
draws, 12 of 16 on each build: `I've removed the locker code and phone number from my memory` with
the phone still stored, or with nothing deleted at all. Every one of those replies ended with
`KEPT_NOTE` listing the kept rows, and each draw that deleted nothing also ended with the note that
nothing was forgotten, so the person reads the true state after a reply that contradicts it.

What would close it: a typed check of the reply against the turn's kept rows, in the safe
direction a reply note takes (the note shows when unsure), that replaces or marks the false
sentence rather than adding a third note, drawn on the rig of those readings with a rule written
first and counted as there. A change to the result texts alone is not the remedy: the base and the
candidate texts gave equal counts.
